# Открытый приём файлов — Manna Vom Himmel

Самостоятельный первый этап до основного Laravel-приложения. Владелец открывает обычную ссылку и загружает файлы с телефона или компьютера. **Нет учётных записей, логина, пароля или секретного ключа.** Это решение принято владельцем проекта отдельно от MASTER-ТЗ.

## Что работает

- Выбор нескольких файлов, перетаскивание файлов/папок, выбор папок в поддерживающих браузерах.
- Последовательная очередь: новые файлы можно добавлять во время загрузки.
- Части по 4 MiB, прогресс, пауза и продолжение, до четырёх автоматических повторов при временном сбое.
- После обновления страницы нужно повторно выбрать те же файлы: в том же браузере передача продолжится с последней принятой части. При выборе папки повторно выбирайте ту же папку: относительный путь входит в идентификатор возобновления.
- SHA-256 каждого переданного блока, защита от повторной записи при потере ответа.
- Поддержка пустых файлов; одинаковые имена не перезаписываются.
- Сортировка `images`, `video`, `audio`, `documents`, `text`, `archives`, `other`, затем год/месяц.
- Любое расширение принимается как оригинал, включая HEIC, RAW, MOV, M4A, DOCX, PDF и ZIP. Архивы не распаковываются; файлы не исполняются и не публикуются.
- Имена недавних файлов хранятся только в браузере отправителя. Общедоступный API показывает суммарные количества, но не выдаёт список оригинальных имён или ссылки на скачивание.
- Каждый готовый оригинал сопровождается `.metadata.json`: исходное имя, исходный относительный путь, размер, время, MIME, категория, стабильный ID и контрольные суммы частей.

Лимит по умолчанию: **20 GiB на файл, 500 GiB на весь каталог**, с сохранением минимум **2 GiB свободного диска**. Незавершённые файлы тоже резервируют место. Лимиты изменяются в локальной конфигурации. HTTP-лимит относится к части, а не к полному видео.

Оставляйте страницу открытой и устройство активным. Браузер запрашивает удержание экрана, если это поддерживается, но мобильная ОС всё равно может приостановить вкладку. Загрузка в фоне после закрытия браузера не обещается. На другом устройстве загрузка начинается заново; повторный выбор уже завершённого файла создаёт отдельный оригинал. Если браузер меняет файл при экспорте из фототеки, он также считается новым.

## Debian + Plesk: первый запуск

Нужны **PHP 8.2+ 64-bit**, расширения **pdo_sqlite** и **fileinfo**, локальная файловая система с поддержкой `flock` и SQLite. Рекомендуемая проверяемая конфигурация — PHP 8.4 FPM. Node.js, npm, Composer, MySQL, Redis и постоянный процесс не требуются. Node **22** используется только в CI для HTTP-тестов.

### 1. Поддомен

В Plesk у подписки `mannavomhimmel.de` создайте поддомен **upload.mannavomhimmel.de**. Настройте DNS на сервер, выпустите сертификат Let's Encrypt и включите перенаправление HTTP → HTTPS. Для загрузки частями браузеру нужен HTTPS.

Ниже команды предполагают, что подписка действительно находится в `/var/www/vhosts/mannavomhimmel.de`. Если Plesk использует другую директорию, замените значение `SUBSCRIPTION`. Не меняйте document root основного сайта.

### 2. Клонирование и подготовка

Выполните по SSH **от root**. Приложение и данные создаются от системного пользователя подписки, а не от root:

```bash
SUBSCRIPTION=/var/www/vhosts/mannavomhimmel.de
SITE_USER=$(stat -c '%U' "$SUBSCRIPTION/httpdocs")
PHP_BIN=/opt/plesk/php/8.4/bin/php

"$PHP_BIN" -v
"$PHP_BIN" -m
runuser -u "$SITE_USER" -- git clone https://github.com/VAtapin/atapin-media.git "$SUBSCRIPTION/atapin-media"

runuser -u "$SITE_USER" -- "$PHP_BIN" "$SUBSCRIPTION/atapin-media/intake/bin/setup.php" \
  --storage="$SUBSCRIPTION/private/manna-intake" \
  --origin=https://upload.mannavomhimmel.de \
  --max-file-gb=20 \
  --quota-gb=500

runuser -u "$SITE_USER" -- "$PHP_BIN" "$SUBSCRIPTION/atapin-media/intake/bin/console.php" status
```

Если PHP 8.4 не установлен в Plesk, установите его через Plesk либо используйте установленный PHP 8.2+ и укажите его путь, например `/opt/plesk/php/8.3/bin/php`. CLI и версия PHP поддомена должны совпадать. При отсутствии `git` root может установить его: `apt-get update` и `apt-get install -y git`. Для закрытого репозитория используйте SSH deploy key с правом чтения или уже настроенную Git-авторизацию; не вставляйте токен в URL и в историю команд.

Если репозиторий уже клонирован именно в эту директорию, вместо `git clone` выполните `git -C ... pull --ff-only` от пользователя подписки. Повторный `setup.php` намеренно отказывается перезаписывать существующую конфигурацию. Для обновлений используйте раздел ниже.

### 3. Настройки именно поддомена в Plesk

**Hosting Settings → Document root:**

```text
atapin-media/intake/public
```

Абсолютный путь должен получиться:

```text
/var/www/vhosts/mannavomhimmel.de/atapin-media/intake/public
```

**PHP:** включить PHP 8.4, обработчик FPM (Apache или nginx).

| Настройка | Значение |
|---|---|
| memory_limit | 128M |
| post_max_size | 8M |
| upload_max_filesize | 8M |
| max_execution_time | 120 |
| max_input_time | 120 |
| display_errors | Off |
| log_errors | On |

Для `open_basedir` разрешите **корень подписки**, чтобы PHP видел код и архив вне `public`. В интерфейсе Plesk обычно подходит `{WEBSPACEROOT}{/}{:}{TMP}{/}`. Если задаёте явные пути:

```text
/var/www/vhosts/mannavomhimmel.de:/tmp
```

У PHP-FPM должны быть права пользователя `SITE_USER` на `private/manna-intake` и `intake/config.local.php`. Не используйте `chmod 777`. Публичной должна быть **только** директория `intake/public`; приложение также откажет в работе, если архив оказался внутри фактического document root. Не создавайте публичных symlink/alias к архиву.

**Apache & nginx Settings:** максимальный размер тела запроса nginx должен быть не меньше **8m**; если используется Apache, его `LimitRequestBody` — не меньше **8388608**. Часто стандартные лимиты уже больше. При ошибке 413 измените соответствующий лимит для этого поддомена в Plesk. Не добавляйте повторную директиву `client_max_body_size`, если Plesk уже генерирует её в том же контексте. Таймаут передачи тела запроса — не меньше 120 секунд. Здесь не нужно разрешать 20 GB в одном HTTP-запросе: приложение передаёт файл частями по 4 MiB.

Официальные инструкции: [настройки PHP в Plesk](https://docs.plesk.com/en-US/obsidian/administrator-guide/70742/), [ограничения загрузки Apache/nginx](https://support.plesk.com/hc/en-us/articles/12376956284695-How-to-upload-large-files-to-a-website-hosted-in-Plesk), [различия PHP-обработчиков](https://doc.plesk.com/en-US/obsidian/administrator-guide/website-management/websites-and-domains/hosting-settings/web-scripting-settings/choosing-the-php-handler.75145/). `.htaccess` не применяется nginx-only; безопасность файлов обеспечивается размещением вне document root.

**Кнопку Node.js в Plesk для этой страницы включать не нужно.**

### 4. Проверка перед передачей ссылки

```bash
curl --fail https://upload.mannavomhimmel.de/api.php?action=overview -H 'X-Intake-Request: 1'
```

Откройте `https://upload.mannavomhimmel.de/`, загрузите текст, фото и видео. Обновите страницу во время передачи видео и выберите то же видео снова: уже принятые части должны сохраниться. Затем выполните:

```bash
runuser -u "$SITE_USER" -- "$PHP_BIN" "$SUBSCRIPTION/atapin-media/intake/bin/console.php" status
runuser -u "$SITE_USER" -- "$PHP_BIN" "$SUBSCRIPTION/atapin-media/intake/bin/console.php" verify
```

`verify` последовательно читает все готовые оригиналы и сверяет части с SHA-256. Это отдельная CLI-операция, которая может быть долгой на большом архиве. Она ничего не изменяет. После успешной проверки можно передавать владельцу обычную открытую ссылку.

## Где находятся данные

```text
private/manna-intake/
├── catalogue.sqlite (+ служебные файлы SQLite)
├── .staging/                         # незавершённые передачи, lock-файлы
├── images/2026/09/<id>--photo.heic
├── video/2026/09/<id>--recording.mov
├── audio/2026/09/<id>--voice.m4a
├── documents/2026/09/<id>--study.docx
├── text/2026/09/<id>--notes.txt
├── archives/2026/09/<id>--archive.zip
└── other/2026/09/<id>--unknown.format
```

У каждого оригинала есть соседний `<имя>.metadata.json`. Имя на диске очищается от управляющих символов и разделителей пути, слишком длинное сокращается; полное исходное имя остаётся в метаданных. Тип выбирается по известному расширению, затем по определённому сервером MIME; неизвестные файлы идут в `other`. Это организационная сортировка, а не проверка содержимого или антивирус.

Никаких endpoint для публичного скачивания, удаления, просмотра или исполнения оригиналов нет. Загруженные файлы пока не импортируются в основную Media Library и не обрабатываются AI. Позже импортёр сможет читать стабильные IDs и метаданные без изменения оригиналов.

## Обновление из Git

В SSH-сессии root снова задайте переменные и выполните:

```bash
SUBSCRIPTION=/var/www/vhosts/mannavomhimmel.de
SITE_USER=$(stat -c '%U' "$SUBSCRIPTION/httpdocs")
PHP_BIN=/opt/plesk/php/8.4/bin/php
runuser -u "$SITE_USER" -- git -C "$SUBSCRIPTION/atapin-media" pull --ff-only
runuser -u "$SITE_USER" -- "$PHP_BIN" "$SUBSCRIPTION/atapin-media/intake/bin/console.php" status
```

Исходники обновляются отдельно от архива. `config.local.php` исключён из Git. Если отключена проверка времени изменения файлов OPcache, перезапустите PHP-FPM **этого поддомена** через Plesk после обновления. Для следующих изменений схемы будут отдельные миграции; не запускайте `setup.php` заново поверх данных.

Включите `private/manna-intake` и локальную конфигурацию в резервное копирование и проверьте восстановление. Для согласованной копии SQLite можно создать отдельный снимок:

```bash
runuser -u "$SITE_USER" -- "$PHP_BIN" "$SUBSCRIPTION/atapin-media/intake/bin/console.php" \
  backup-catalogue "$SUBSCRIPTION/private/intake-catalogue-backup.sqlite"
```

Целевой файл должен быть новым. Снимок каталога не заменяет резервную копию самих оригиналов и `.metadata.json`. Готовые файлы неизменяемы; для полного снимка используйте снапшот файловой системы/бэкап Plesk либо временно остановите приём на время согласованной копии каталога и данных. Незавершённые передачи не удаляются автоматически.

## Проверки разработчика

```bash
php intake/tests/archive.php
node intake/tests/http.mjs
node --check intake/public/app.js
```

HTTP-тест поднимает настоящий PHP-сервер на свободном loopback-порту, создаёт изолированный временный архив, передаёт несколько частей и проверяет оригиналы на диске. Нужен Node 22+. GitHub Actions запускает проверки на Linux с PHP 8.2/8.4 и Node 22.

Дизайн продолжает `UI/approved/`: navy, gold, светлые поверхности. Интерфейс немецкий; тексты отделены в `lang/de.php` и `public/lang-de.js`. Чтение очереди через WebMCP доступно только в поддерживающих браузерах и не управляет файлами.
