# Atapin Media — статус проекта

Актуализировано: 14 сентября 2026 года.

## Реализовано

- Все девять overview-страниц используют общую рукописную надпись вне featured-медиа: справа на desktop, ниже медиа на ширине ≤1600 px. Главная сохраняет свою фразу; Videos, Beiträge, Bücher, Live, Podcast, Community, Über uns и Mission получили разные короткие христианские тексты de/en. Белое облачко усилено под основным hero-текстом и боковыми надписями, сохраняя мягкое затухание и яркий фон вне текста. CSS cache version обновлена.
- Убраны маленькие декоративные стрелки у шести карточек разделов главной, в общих ссылках заголовков контентных панелей, Bücherregal и заглушках; ссылки сохранены. Стрелки кнопок действий и пагинации не менялись.
- Назначение по длительности в Import Center использует существующие переводы imports.posts/videos/shorts вместо отсутствующих imports.target_*; список показывает Beiträge, Videos, Shorts, а не translation keys.
- Карточка Google Takeout в Import Center содержит только краткую подпись. Подробная инструкция перенесена в существующую справку «?» окна; дублирующий текст убран из выбранного Takeout-панеля. Справка de/en актуализирована для private/Takeout, SHA-256-копирования, прямой выдачи public/media и настроенного правила длительности.
- Media Desktop deeplink `?open=...` выполняется один раз и удаляется из текущего адреса без перезагрузки; остальные параметры и fragment сохраняются. Закрытая Community больше не открывается повторно при reload/повторном входе; сохранённые открытые окна и новые явные deeplinks продолжают работать. Версия desktop-os.js обновлена для browser cache.
- Основа: Laravel 13 / PHP 8.4, авторизация, пользователи и RBAC, настройки с зашифрованными секретами, аудит; backend проектов, задач и календаря.
- Media Desktop: 19 программ, окна и Snap Layouts, сохранение персонального расположения, четыре approved-набора значков, общие настройки оформления и отдельные профили пользователей. Einstellungen — native-интерфейс с локализованными редакционными текстами и управлением пользователями. Live Studio подключён к desktop-окну через JSON API: список, создание, редактирование, публикация, OBS-вход, ротация ключа и получение RTMPS-данных больше не требуют отдельной HTML-ссылки.
- Media Library: цельные материалы и отдельная файловая галерея; поиск, фильтры, protected preview/download с HTTP Range, resumable upload папок/файлов с pause/resume/stop, теги, коллекции, редактирование плейлистов и массовые действия. Удаление материалов обратимое; замена cover/video/attachments не перезаписывает originals и чужие связи. Проверка квоты resumable upload совместима с MariaDB: зарезервированные байты считаются без сырого выражения с колонкой `offset`.
- Import Center: серверные папки/архивы, загрузка архивов до 20 GB, существующие intake/YouTube archives и публичные ссылки через collector/yt-dlp. Фоновая очередь, stop/retry, checkpoints, отдельное окно Import-Vorgänge, пообъектный отчёт и индикация стадии/файла/байтов/давности сообщения. Активность процесса очереди не выдаётся за подтверждение завершения конкретного импорта.
- Publishing: Website запускает внешнюю очередь без подтверждения; YouTube запрашивает только public, сохраняет video/broadcast ID до обложки/привязки и продолжает повтор с этого ID. Работа захватывается атомарно, ручной retry разрешён только для failed; due retries и Instagram processing checks запускаются существующим scheduler. OAuth проверяет одноразовый непустой state, disconnect очищает encrypted credentials и блокирует работу. Обратный YouTube import остаётся review-only, связывает собственные outbound IDs с исходными материалами и не отправляет импорт обратно при включении сайта. Live распознаётся по существующему public_section=live; один reusable key, foreground MediaMTX/HLS→ffmpeg relay без PID/JSON-менеджера, завершение с повтором через общую очередь. Медиа используют текущий canonical public/media/SHA-256 contract. Production API/вещание не проверены; подробности в docs/PUBLISHING.md.
- Takeout: единая распакованная папка private/Takeout либо multipart ZIP; CSV задают IDs, тексты и связи, HTML archive_browser.html проверяет файловый состав. При отсутствии отчёта сохранён fallback с предупреждением. Импортируются видео, Beiträge, изображения, опросы/Quiz, комментарии, Livechats, плейлисты и контоданные; неизвестные схемы остаются в исходной выгрузке и перечисляются в отчёте.
- Повторные импорты объединяют записи по source/ID и originals по SHA-256/размеру/MIME; дополняют metadata/assets, сохраняют ручные правки, исходные версии, trash и исключённые связи. Обложки/комментарии/playlist positions связываются по достоверным IDs и metadata; неоднозначности остаются в отчёте, а не угадываются.
- Lokale Videos prüfen: серверный отчёт по registered originals, размерам и ffprobe; отдельная браузерная проверка same-origin HTTP Range, декодированного кадра, seek и короткого воспроизведения с сохранённым результатом.
- ИИ-разметка импорта: экономная обработка имеющихся текстов/метаданных/готовых субтитров и небольших изображений; журналы, snapshots и защищённая отмена. Takeout не запускает автоматические платные ИИ-задания и не превращает отдельные картинки в самостоятельные Beiträge.
- Import Center имеет сохраняемые настройки назначения по длительности: enabled, min/max секунд, Beiträge/Videos/Shorts. Manna получает первоначальное правило 14–16 → Beiträge; настройки, включая отключение, имеют приоритет. Импорт автоматически назначает подходящие unsorted video/short записи без ИИ, сохраняя файлы/комментарии/плейлисты; ready/manual/ai/trash защищены. ИИ получает то же текущее правило как доверенную подсказку. `.env` не меняется.
- Старый /upload/ отключён: страница перенаправляет в Desktop, API возвращает 410; приватный intake archive сохранён, прежний интерфейс доступен в Git.
- Public Website: все 10 approved-страниц — главная, Videos/detail, Beiträge/detail, Bücher/detail, Live, Podcast, Community. Каталоги, детали, поиск, фильтры, пагинация, вкладки и локальные плееры читают БД; пустые блоки видимы с обозначением отсутствия данных. Live-плеер передаёт MediaMTX cookie-check внутри `/_live/`, а nginx-инструкция явно переписывает служебные редиректы обратно в этот префикс. Если Live-событие завершено или HLS недоступен, плеер показывает афишу/брендированный fallback вместо чёрного видео и сетевой ошибки; для следующего события выводятся его cover, название, дата и описание. В публичном Live-блоке технические подписи заменены данными события, напоминания вынесены в компактные цветные кнопки над плеером без Email/Push-подсказок, а чат доступен гостям и зарегистрированным пользователям, показывает отправителю результат проверки, использует увеличенную область сообщений и компактное временное уведомление. Главная выбирает hero-видео среди опубликованных Videos: отмеченные флажком «Auf der Startseite anzeigen» имеют приоритет; без отметок берётся самое новое видео. Livestream в этот выбор не попадает. Hero-фон и боковая надпись используют локальные градиенты и текстовые элементы approved-композиции; публичный логотип разделён на знак и текст. Public CSS/JS изолированы от Desktop.
- Public Video analytics: фактический просмотр регистрируется при запуске опубликованного локального видео, сессия учитывается не более одного раза в сутки для одного видео; блоки «Beliebte Videos» сортируются по этим записям, а не по неподтверждённому `metadata.views`. Просроченные запланированные Live-события при обращении к сайту или Live Studio переводятся в `ended` с причиной `missed_schedule`; в ближайшие эфиры попадают только будущие даты.
- Public account: `/konto` оформлен как полноценный адаптивный личный кабинет в Manna-стиле; активность, прогресс, browser reminders, подтверждение email и профиль/пароль показаны в отдельных карточках без сырого JSON и внутренних translation keys.
- Public account разделяет staff и обычных пользователей: аккаунты с правами управления пользователями/настройками не получают запрос подтверждения email; опубликованные медиа и загрузки остаются в Media Desktop, а `/konto` работает только с личными состояниями текущего пользователя.
- Staff-аккаунт в `/konto` не читает и не показывает activity, browser reminders или профиль/пароль; единственное действие — перейти в Media Desktop. Staff также не создаёт public content states через публичные реакции.
- Обычный `/konto` собирает личную историю из существующих данных: покупки по email, newsletter-подписки, сохранённый контент и прогресс, собственные Community/Kommentar/Livechat-сообщения, Buchrezensionen и вопросы AI-помощнику с переходами к исходным материалам.
- История сообщений, Buchrezensionen и вопросов AI-помощнику в `/konto` не обрезается искусственным лимитом: большие списки доступны постранично, а счётчики показывают общее количество записей.
- Ошибка Blade ParseError на `/konto` исправлена: тип сообщения вычисляется в контроллере, а не через фигурный `match` внутри Blade-выражения.
- Шаблон `/konto` дополнительно переписан в многострочную Blade-разметку с балансом всех условных блоков; устранён повторный `unexpected token endif` при компиляции кабинета.
- Исправлена синтаксическая ошибка в `public/card.blade.php`, из-за которой production Blade-компиляция выдавала `unexpected token "endif"` и страницы `/live` и `/videos/...` отвечали HTTP 500.
- Brand background: предоставленная владельцем панорама `manna-mountains.png` установлена как единый hero-фон главной и публичных разделов, а также стандартные горные обои Desktop; на главной approved-композиция `01-start` получила overlay-шапку и измеренную высоту hero около 400 px; прежний временный фон больше не используется в этих местах.
- Über uns, Mission и юридические тексты редактируются в настройках. Контактная форма сохраняет обращения в защищённый inbox и пересылает через очередь на settings.contact_email; повторные попытки, видимый статус и ручной retry. Email Live-напоминания поддерживают PHP/sendmail Plesk без обязательного внешнего SMTP.
- Web Push Live: согласие и разрешение браузера, подписка/отмена на событие, encrypted subscriptions, приватные стабильные VAPID keys, scheduler и retryable jobs с проверками публикации/времени. Поддержаны ограниченные endpoints служб доставки Google/Mozilla/Apple/Microsoft.
- Upload-профили: отдельные интерфейсы загрузки сохраняются в каждом разделе, а общий resumable-механизм проверяет профиль назначения. Изображения для Media Library, Live-афиши, Cover, аватара и обоев автоматически оптимизируются в браузере; сервер повторно проверяет MIME, размеры и итоговый объём. Видео, архивы и вложения не перекодируются.
- Live: обновляемый чат и счётчик активных browser sessions. Гости и зарегистрированные пользователи отправляют сообщения без авторизации и лимитов; сообщения проходят фоновую AI-проверку, безопасные публикуются автоматически, спорные попадают в отдельную очередь человека. Модерация находится только в защищённом Community-модуле Media Desktop; публичная страница не содержит управления очередью. Опубликованный чат обновляется через heartbeat. Live Studio — единственный административный интерфейс вещания и работает через JSON API внутри `/desktop`; отдельный legacy `/desktop/live` HTML-интерфейс удалён. Для события в Live Studio можно загрузить одно защищённое изображение-афишу через существующую Media-библиотеку; оно связывается как `cover_media_id` и используется публичными Live-карточками/анонсом. Загрузка афиши теперь показывает отдельные состояния выбора, подготовки, процента передачи, привязки, успеха и ошибки с возможностью повторного сохранения. Будущие события не попадают в «Aufzeichnungen»: записи отделены фильтром `live_status=ended`, а Live Studio сортирует текущие/запланированные события выше завершённых.
- OBS → MediaMTX → локальный плеер: защищённое управление событиями и encrypted keys, общий RTMPS ingest path/key для всех событий, выбор enabled-события по live status и расписанию, ingest/HLS authorization, pinned installer/start/status, private recording hooks и регистрация MP4. Новый заголовок не требует менять OBS; локальный RTMP/SSH остаётся административным fallback, зрители — через nginx /_live/. В Live Studio показывается одна общая RTMPS-адреса, без SSH-инструкций для стримера. Сертификат/ключ и firewall остаются одноразовой серверной настройкой.
- Посетители: регистрация без административной роли, email verification, личный /konto с собственными реакциями/закладками/прогрессом/напоминаниями, отменой подписок и изменением профиля; восстановление пароля через existing Laravel broker и encrypted queue.
- Newsletter: double opt-in, queued confirmation, подписанные ссылки подтверждения/отмены, согласие, cooldown и статусы доставки.
- Книги: защищённый редактор metadata/цены/статуса; verified читатели отправляют отзывы, изменения требуют повторной модерации. Community: вопросы/обсуждения посетителей, правила из настроек, защищённая publish/reject модерация с аудитом.
- Public header: все публичные страницы используют единую оболочку header; пустая верхняя полоса Bücher удалена, кнопка Mitmachen получила безопасный отступ и не обрезает иконку, Live получил согласованный фон страницы.
- Public UI shell: один переиспользуемый overview-header/hero используется главной и всеми разделами, включая Live; один общий detail-header используется страницами отдельных видео, Beiträge, книг и выбранных Live-событий, а публикационные данные меняются через содержимое страницы. Live-плеер и чат выводятся только для выбранного события; служебные overview/about-страницы используют локализованный общий hero без сырых translation keys. Hero теперь имеет один общий desktop/mobile-каркас и геометрию для всех overview-страниц; отсутствующее featured-медиа получает брендированную fallback-заглушку, а fallback URL вычисляется до разметки.

## Текущее состояние и решения

- Community moderation: гости и зарегистрированные пользователи могут отправлять community-посты, комментарии и Livechat без авторизации и частотных лимитов. Автор сразу видит собственное сообщение в состоянии проверки; остальные видят его только после AI-разрешения. AI-подозрительные сообщения остаются у автора красными как «заблокировано» и попадают в human-review очередь; после трёх AI-блокировок отправка новых сообщений запрещается. Управление очередью вынесено в защищённое окно Community внутри Media Desktop; публичный сайт не показывает административные действия.

- Self-hosted single-tenant; Manna Vom Himmel — первая установка, не отдельный Core. Основной UI немецкий, новые строки локализованы.
- Publishing decision: публикация Website остаётся немедленной и запускает внешние Jobs без дополнительного подтверждения; обратная синхронизация YouTube всегда создаёт `review`/`public_published=false`. `manna-youtube-runtime` не используется как основа новой интеграции; для review-импорта предусмотрен отдельный `yt-dlp`-процесс.
- Blade и progressive JavaScript без обязательной Node-сборки. Composer используется для PHP-зависимостей Laravel, включая minishlink/web-push; не нужен при обычном обновлении текстов/Blade.
- Production checkout: /var/www/vhosts/mannavomhimmel.de/httpdocs; document root: httpdocs/platform/public; runtime: private/atapin-platform. PHP: /opt/plesk/php/8.4/bin/php. Queue/scheduler — Plesk scheduled tasks, без самостоятельной установки systemd.
- MediaMTX после reboot запускается отдельной Plesk command task каждую минуту; lock предотвращает второй процесс. RTMPS использует файлы private/atapin-live/rtmps.crt и rtmps.key, не входящие в Git.
- Предпочтительный Takeout источник: /var/www/vhosts/mannavomhimmel.de/private/Takeout; TAKEOUT_FOLDER позволяет переопределить путь. Takeout и `.env` сохраняются полностью. Владелец сообщил о полном сбросе БД и создании нового администратора; private/manna-youtube удалён владельцем, runtime сборщика сохранён. Новых удалений БД/серверных файлов агент не выполнял.
- Новые бесплатные видео, audio/podcasts, изображения и субтитры физически сохраняются в /var/www/vhosts/mannavomhimmel.de/httpdocs/platform/public/media с именем SHA-256 содержимого. Admin/public UI получают прямые static URLs `/media/<hash>.<ext>`, без симлинков и PHP-передачи бинарных файлов. Takeout импортируется по одному полному объекту: bytes готовятся до короткой транзакции metadata/assets/comments/playlist links. Исходный экспорт сохраняется; retry/checkpoints не создают дубликаты. Подробнее: docs/MEDIA-STORAGE.md.
- Публикация материалов не автоматическая; только published ready records/children видны на сайте, архивные контоданные исключены из public и ИИ. По решению владельца бесплатные бинарные медиа публично адресуемы независимо от редакционного статуса. Документы, архивы и staging остаются private. Платные video/audio потребуют отдельного защищённого storage/выдачи с удалением публичной копии, не просто флажка на странице.
- Видео/файлы публикуются с нашего сервера, без YouTube fallback/кнопок перехода. Адреса источников остаются provenance; приватные originals не раскрываются.
- Платное прослушивание/анализ audio/video не входит в текущий план. Реальные production-письма, Push и вещание проверяет владелец; отсутствие этих проверок у агента не считается недоработкой реализации.
- Владелец подтвердил, что новый импорт ещё не запускался и каталог пустой. Правило длительности применяется автоматически при новом импорте, не публикует материалы и не запускает платный ИИ. Publishing исправлен отдельным commit `1b0cae2`; его изменения не входят в блок импорта/public tests. Секреты и клиентские данные не входят в Git.

## Известные ограничения

- На ширине 820 px верхнее desktop-меню главной выходит за viewport; существующие header-стили в исправлении боковой надписи не менялись. Требуется отдельная корректировка breakpoint меню.
- 100% pixel match не подтверждён; пустые блоки пока намеренно включены.
- Оплачиваемый checkout не реализован: требуется выбор способа оплаты владельцем. Покупка пока через контакт; платные PDF не выдаются публично.
