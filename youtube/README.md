# Публичный архив Manna Vom Himmel с YouTube

Канал: https://www.youtube.com/@MannaVomHimmel — `UC32nXxuzjY7ExrDgzSAQNXQ`.

Полная личная выгрузка владельца из YouTube Studio или Google Takeout
хранится отдельно от этого публичного снимка. Правило хранения и план
последующего импорта зафиксированы в
[`MANUAL_ARCHIVE_IMPORT.md`](./MANUAL_ARCHIVE_IMPORT.md).

Сбор выполняется **на сервере**, без API-ключа, логина, cookies аккаунта и обработки содержимого. Используются Python и yt-dlp; Node 22 из Plesk нужен загрузчику для работы с YouTube, FFmpeg — для соединения видео и звука без перекодирования. PHP сайта и страница `/upload/` продолжают работать независимо.

## Установка и запуск в Debian/Plesk

В SSH, в существующем Git-каталоге:

```bash
cd /var/www/vhosts/mannavomhimmel.de/httpdocs
git pull --ff-only
bash youtube/bin/plesk.sh install
bash youtube/bin/plesk.sh start
```

Установка создаёт Python-окружение в приватной папке подписки. При запуске `install` от root недостающие `python3-venv` и `ffmpeg` устанавливаются через apt. Сам сбор всегда запускается от владельца `httpdocs`, а не от root. При установленных зависимостях всё можно запускать от пользователя подписки.

Используется существующий Node `/opt/plesk/node/22/bin/node`; если его нет — `node` из PATH, обязательно версии 22+. Для другого расположения: `PLESK_NODE_BIN=/путь/к/node bash youtube/bin/plesk.sh install` (так же передавайте переменную при `start`). Отдельную Node-программу в панели Plesk включать не нужно.

После `start` можно закрыть SSH — сбор продолжится. Второй процесс для того же архива блокируется файловой блокировкой. Это разовый процесс: после перезагрузки сервера или завершения требуется снова выполнить `start`; автоматического расписания нет.

```bash
bash youtube/bin/plesk.sh status
bash youtube/bin/plesk.sh logs
```

`status` показывает `active`, состояние текущего запуска и количества завершённых/неполных материалов. `logs` показывает журнал; Ctrl+C выходит из просмотра, не останавливая сбор.

Для работы в открытом терминале вместо фона: `bash youtube/bin/plesk.sh run`. Ctrl+C прерывает такой запуск; следующая команда `start` продолжит сбор. Фоновый процесс можно остановить `kill -TERM PID`, взяв PID из `status`, предварительно убедившись, что `active` равно `true` и процесс относится к этому сборщику.

## Что сохраняется

- **Видео и Shorts**, доступные записи трансляций: лучшее доступное видео и звук. Обычно результат — MKV; исходные потоки соединяются без перекодирования. YouTube уже мог перекодировать оригинал автора.
- **Название, описание, ссылка, YouTube ID, даты, теги, главы, доступная статистика и прочие метаданные** — JSON и отдельные текстовые файлы.
- **Комментарии под видео и ответы** — JSON с ID комментария, родительским ID, текстом, автором и прочими полями, которые вернул YouTube. Сортировка «сначала новые», без заданного лимита количества. Предупреждения и число реально полученных комментариев сохраняются: скрытые/удалённые комментарии и меняющиеся счётчики не считаются восстановленными.
- **Обложка**, загруженные автором субтитры и исходные автоматические субтитры. Автоматические переводы на сотни языков не заказываются. Сохранённый чат трансляции выгружается, если YouTube предоставляет его как отдельную дорожку.
- **Плейлисты**: название, описание, обложка, исходные метаданные, `ordered_items` с порядком роликов и их ID. Один локальный ролик можно связать с любым числом плейлистов. Чужие ролики из плейлистов не скачиваются; их ссылки и позиции сохраняются.
- **Beiträge / публикации**: все страницы, которые отдаёт публичная вкладка Posts, без ограничения по дате. Сохраняются текст, ссылки, вложения, картинки, данные опросов и сырой JSON. Относительные даты вроде «2 years ago» сохраняются как получены, без выдумывания точной даты. Обсуждения под публикациями отдельно не выгружаются; комментарии в этой версии собираются под видео.

**Ограничение истории Beiträge:** при проверке этого канала 11 сентября 2026 года публичная выдача закончилась на 200 публикациях, самая старая из полученных имела метку «5 months ago». Это не весь заявленный двухлетний архив. При получении 200 и более записей отчёт помечает возможный предел публичной выдачи (`possible_history_limit`) и состояние `partial`; зацикливание пагинации также считается неполным сбором. Более старые публикации могут оставаться доступны по прямым ссылкам, но автоматически обнаружить их через эту выдачу не удалось. API-ключ для этого сборщика не требуется и этот предел не снимает.

Приватные, доступные только по ссылке и требующие подписки материалы не скачиваются. Текущие эфиры и запланированные премьеры отмечаются как отложенные: их записи можно собрать следующим запуском. Сборщик сверяет принадлежность каждого видео каналу. Неизвестная принадлежность означает ошибку, а не скачивание чужого файла.

## Расположение файлов

```text
/var/www/vhosts/mannavomhimmel.de/private/
├── manna-youtube-runtime/             # отдельное Python-окружение
└── manna-youtube/
    ├── collection.log                # журнал работы
    ├── report.json                   # состояние запуска и ошибки вкладок
    ├── inventory.json                # список обнаруженных роликов
    ├── channel/                      # метаданные вкладок канала
    ├── playlists/
    │   ├── <playlist-id>.json         # описание и ordered_items
    │   └── <hash>.image               # изображения обложек
    ├── posts/
    │   ├── index.json                # порядок и метки дат всех публикаций
    │   └── <post-id>/
    │       ├── post.json
    │       ├── text.txt
    │       └── <hash>.image           # исходные байты изображения
    └── items/<youtube-id>/
        ├── video.mkv
        ├── title.txt
        ├── description.txt
        ├── source.url
        ├── metadata.json
        ├── comments.json
        ├── thumbnail.webp
        ├── subtitles/
        └── state.json                # результат каждого этапа и SHA-256 видео
```

Расширения видео, обложек и субтитров зависят от источника. Файлы `.image` содержат исходные JPEG/PNG/WebP-данные без изменений; соответствующие URL сохранены в JSON. В Git отправляется только код. Этот архив пока не импортируется в каталог ручной загрузки и не публикуется на сайте.

## Продолжение и отчёт о полноте

Повторите `bash youtube/bin/plesk.sh start`: новые записи будут добавлены, завершённые ролики пропущены, неуспешные этапы повторены. Отсутствующий файл или изменившийся размер обнаруживается по манифесту. Ошибка комментариев или субтитров не мешает сохранить видео и обложку. Незаконченные передачи продолжаются через `.part`; при повреждении обнаруженного видео оно сохраняется с суффиксом `.damaged`, затем скачивается заново.

При обычном повторном запуске список канала, плейлисты и публикации перечитываются. Завершённые наборы видео сохраняются как снимок на момент сбора: уже успешно выгруженные комментарии и статистика автоматически не обновляются. Ранее сохранённое не удаляется, если исчезло с YouTube. Для повторения неудачных загрузок без повторного обхода публикаций: `bash youtube/bin/plesk.sh start --use-inventory`.

Состояние `complete` означает, что закончились запрошенные этапы, а не что YouTube предоставил когда-либо существовавшие или скрытые данные. Предупреждения, пропуски и ошибки остаются в `report.json` и `items/<id>/state.json`. `partial` требует просмотра этих файлов и, при необходимости, повторного запуска. Ограничение YouTube 429 или требование проверки пользователя не обходятся; ключ API сам по себе их не устраняет.

Резерв свободного места — **5 GiB**. Если места становится меньше, сбор останавливается. Существующие файлы сохраняются. Это общий предел свободного места диска, а не квота ручного загрузчика. При необходимости параметр задаётся явно: `bash youtube/bin/plesk.sh start --reserve-gib 10`.

Пробный режим `run --limit 1` обходит вкладки, публикации и плейлисты, но скачивает только один ролик. `run --inventory-only` собирает каталог, публикации и их картинки без видео. Для больших архивов используйте обычный фоновый `start`.

## Проверка разработки

```bash
python -m pip install -r youtube/requirements.txt
python -m unittest discover -s youtube/tests -v
```

Тесты проверяют продолжение после ошибок, отсутствие повторного скачивания видео, сохранение ответов на комментарии, ограничение архива собственным каналом, защиту путей, файловую блокировку и проверку настоящего видео через FFprobe. CI работает на Linux с Node 22. Пробная выгрузка публичного Shorts отдельно проверяется против YouTube; CI не зависит от доступности YouTube.

Версия yt-dlp закреплена вместе с адаптером публикаций. При изменении выдачи YouTube обновляйте зависимость и проверяйте сбор публикаций перед полной выгрузкой. Документация: [yt-dlp](https://github.com/yt-dlp/yt-dlp), [Node/EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS).
